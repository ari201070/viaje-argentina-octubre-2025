# V0.6 — Módulo de Documentos y Vouchers de Viaje

## Objetivo

Permitir almacenar, visualizar y gestionar documentos de viaje (PDFs, imágenes de vouchers, tickets, reservas) con soporte offline mediante IndexedDB. Los archivos se guardan como Blob en la base de datos local del navegador, permitiendo acceso sin conexión durante el viaje.

## Arquitectura

### Almacenamiento: IndexedDB

- **Base de datos**: `argentina_trip_db`
- **Object Store**: `documents`
- **Key path**: `id` (autoincrement)
- **Índices**: `category`, `cityId`, `createdAt`

### Estructura de un documento

```js
{
  id: Number,           // auto-generado por IndexedDB
  name: String,         // nombre original del archivo
  type: String,         // MIME type (ej: "application/pdf", "image/jpeg")
  size: Number,         // tamaño en bytes
  blob: Blob,           // archivo binario almacenado
  category: String,     // "Vuelos" | "Alojamiento" | "Excursiones" | "Seguro" | "Cambio" | "Varios"
  cityId: Number|null,  // ID de ciudad asociada (opcional)
  notes: String,        // notas del usuario (opcional)
  createdAt: String,    // ISO timestamp
}
```

## Componentes

### `src/utils/idbStorage.js`

Wrapper de IndexedDB nativo con Promises:

- `openDB()` → Abre/crea la base de datos `argentina_trip_db` (versión 1)
- `putItem(store, item)` → Guarda un documento (add o update)
- `getAllItems(store)` → Lista todos los documentos
- `getItem(store, id)` → Obtiene un documento por ID
- `deleteItem(store, id)` → Elimina un documento por ID
- `clearStore(store)` → Borra todos los documentos

### `src/hooks/useDocuments.js`

Hook que gestiona operaciones CRUD:

- `documents` → array de documentos en estado
- `loading` → boolean de carga
- `saveDocument(doc)` → guarda un documento y refresca la lista
- `deleteDocument(id)` → elimina un documento y refresca la lista
- `getDocumentUrl(id)` → retorna URL temporal (`URL.createObjectURL`) para visualización
- `revokeUrl(url)` → libera memoria con `URL.revokeObjectURL`

### `src/components/documents/DocumentUploader.jsx`

Formulario de carga con:

- Input file (accept: `.pdf,.png,.jpg,.jpeg`)
- Selector de categoría (Vuelos, Alojamiento, Excursiones, Seguro, Cambio, Varios)
- Selector de ciudad (dropdown desde `cities.json`)
- Campo de notas (textarea opcional)
- Botón "📤 Subir documento"
- Validación de tamaño (máx 10 MB por archivo)

### `src/components/documents/DocumentList.jsx`

Grid de vouchers con:

- Thumbnail/ícono según tipo (PDF 📄, imagen 🖼️)
- Badge de categoría con color
- Nombre del archivo y tamaño formateado (KB/MB)
- Ciudad asociada (si tiene)
- Botón "👁️ Ver" → abre el visor
- Botón "🗑️ Eliminar" → elimina con confirmación
- Estado vacío: "📄 No hay documentos cargados"

### `src/components/documents/DocumentViewer.jsx`

Modal visor con:

- Overlay semi-transparente
- Para PDFs: `<iframe>` con `URL.createObjectURL`
- Para imágenes: `<img>` en alta resolución
- Botón "✖ Cerrar" que libera la URL con `URL.revokeObjectURL`
- Muestra metadata (nombre, categoría, tamaño, notas)

### `src/components/documents/DocumentDashboard.jsx`

Contenedor principal con:

- Filtros: por categoría (dropdown) y por ciudad (dropdown)
- Contador de documentos totales
- `DocumentUploader` + `DocumentList` integrados
- Gestión del estado del visor (qué documento está abierto)

## Consideraciones offline

- IndexedDB funciona sin conexión
- Los Blob se almacenan localmente en el navegador
- `URL.createObjectURL` funciona offline
- El Service Worker no intercepta `blob:` URLs (es correcto, no necesita cachearlas)
- Los datos persisten entre sesiones

## Limitaciones conocidas

- Máximo 10 MB por archivo (validación en el uploader)
- Cuota de almacenamiento del navegador (típicamente 50-80% del espacio disponible)
- No hay sincronización con la nube (futuro: sync con backend)
